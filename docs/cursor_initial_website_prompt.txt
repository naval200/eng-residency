# Cursor prompt: build the initial Rishikesh Learning Residency website

You are working in an existing codebase. First inspect the repository, identify its framework, styling system, existing routes, and conventions, then implement the page using the current stack. Do not replace the project setup or introduce a new framework. Keep the implementation small and easy to maintain.

## Goal

Build a polished, responsive one-page website for a **30-day self-directed learning residency in Rishikesh**. The working name is **Rishikesh Learning Residency**. The first cohort is aimed especially at software engineers and technology professionals between jobs who want to use a month to learn something difficult, build a project, and spend time with a good peer group.

This is not a bootcamp, job-placement service, online course, formal yoga retreat, or workation package. We do not provide a fixed curriculum, course library, instructors for every subject, certification, or a promise of employment. Participants create their own learning track and use their own resources. The product is a place to focus, community, accountability, coordination, and optional local experiences.

Do not invent the cohort dates, venue address, testimonials, number of alumni, partnerships, contact email, provider commitments, or final prices. Make the pricing status explicit.

## Core positioning and copy

Use this general voice: calm, direct, human, practical, not corporate. Avoid AI/startup buzzwords, generic SaaS language, excessive cards, fake urgency, and long paragraphs.

Suggested hero:

**Headline:** A month to learn something difficult, with good people around you.

**Subheading:** A self-directed learning residency in Rishikesh for people between jobs and others taking a deliberate learning break. Choose what to study, make a plan, and work on it alongside people doing the same.

**Primary CTA:** Express interest  
**Secondary CTA:** How it works

The primary CTA must open a proper, mobile-friendly residency interest form. The form should feel thoughtful and human, not like a generic SaaS lead form. Because it asks several questions, use a dedicated `/apply` route or a well-designed multi-step form rather than a tiny modal. A user should be able to save nothing and return later; do not store personal data in local storage.

Suggested short intro:

You bring the goal and learning material. We bring a place to focus, a community that helps you keep going, and a few ways to spend time outside the desk. There is no fixed curriculum. Peers and the host check in on progress; you own the work.
